# Book Video Agent Guide

This repository is an open-source, natural-language workflow for producing short book videos. Keep reusable code, templates, owned assets, and distilled methods in Git. Keep credentials, private book data, downloaded reference media, generated episode work, and account data local. The consolidated transcript-analysis under `assets/reference-videos/` is a user-approved text reference; the source videos are not tracked. Third-party scripts are not covered by Apache-2.0, so confirm redistribution rights before external publication.

## Startup Checklist

For the first user message in this repository, including a simple greeting such as "你好", run the startup checklist before normal task work unless `.book-automation-state.json` already exists and the user is asking an unrelated repository-maintenance question.

1. Resolve the current repository root with `git rev-parse --show-toplevel`; never hard-code a previous clone path. Check Codex capabilities first: the HyperFrames plugin/Skill and built-in bitmap image generation are capabilities, not user-installed project dependencies. Use them directly when available; do not ask the user to install a separate image model or HyperFrames Skill.
2. Check local runtime prerequisites in one pass by running `node scripts/init.mjs` from the resolved repository root. Do not replace this with an ad-hoc `command -v` plus parsed `--version` output: FFmpeg and FFprobe commonly write version banners to stderr, so a blank stdout is not a missing-command signal. Trust the command exit status and the JSON check result. If Node.js 22+, `npx`, FFmpeg/FFprobe, or `whisper-cli` are missing, report the complete list and ask for one confirmation before installing them. After confirmation, the Agent may install them with the available platform package manager; never install or change system packages silently. The repository does not auto-install these through a project script.
3. HyperFrames runs through `npx hyperframes@0.7.33`, so the first check or render may need npm registry access even when the HyperFrames Skill is available. If `npx` reports `ENETUNREACH`, `EACCES`, `ENOTFOUND`, `ENOTCACHED`, registry access blocked, or a system network policy failure, classify it as an environment/network issue and immediately retry the same check/render with the execution tool's network-capable escalation. Do not ask the user for a second confirmation or ask them to repeat the workflow. Only report the blocker if the escalation itself is denied or fails. Try the local npm cache with `npx --offline` only as a quick fallback; it cannot replace network access when the package is not cached.
4. Check the model at `<repo-root>/assets/models/whisper/ggml-base.bin` using file existence and size, not `ls` output alone; a valid file is at least 100 MB. If missing, ask to download it as part of the confirmed setup, then run `node scripts/download-whisper-model.mjs`. If the download fails, first look for an enabled computer proxy or proxy environment variable; use it for a retry with `--proxy`, asking the user to enable their proxy when none is active. Do not change system network settings silently. If that fails, give the user the browser URL `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.bin`, then install the user-provided file with `node scripts/download-whisper-model.mjs --from "<local-path>"`.
5. Ensure the official Tencent WeChat Reading Skill is installed and enabled through the agent's skill installer when absent; do not ask whether to enable it and do not vendor its source into this repository.
6. If the initialization result reports `wereadApiKey: true` or `weread: enabled`, treat WeChat Reading as configured and never ask for the key again. Only when it is missing, ask once whether the user wants to connect WeChat Reading. After consent, open [微信读书 Skills 官网](https://weread.qq.com/r/weread-skills) in the browser/computer tool and assist with its login-to-key flow; do not stop at returning a link. The user must complete login, QR/OTP, or CAPTCHA directly; never ask them to disclose passwords, codes, or cookies. If the page exposes the generated key and the current tools can transfer it safely, write it directly to local `.env` with mode `0600` without showing it in chat, logs, or command arguments. Otherwise ask the user to enter it into the hidden local TTY prompt from `node scripts/init.mjs --configure-weread` (never ask them to paste the key into chat). If login, browser access, or key retrieval gets stuck, ask the user to handle only that step or describe what is on the page. Rerun plain `node scripts/init.mjs` and confirm `wereadApiKey: true`; if the user declines, continue with public research.
7. Run `scripts/init.mjs` after the dependency and Skill checks. It creates local state and the private pipeline file without asking a second WeChat Reading enablement question.

After a body voiceover is supplied, run `node scripts/create-body-timings.mjs "<book>" [script-version]`. FFmpeg silence boundaries provide timings; Whisper token timestamps are never used. Merge extra speech boundaries or estimate over speech duration when counts differ, mark the result for review, and continue. Whisper checks TTS text only; suspected omissions, repeats, ASR errors, and unavailable output are review warnings, never timing/render gates. Keep `script.csv` as subtitle truth. Jianying audio skips Whisper. Pass only the book title as Whisper `--prompt` (or omit it); long Chinese prompts can bias whisper.cpp. Do not silently discard speech or infer the TTS opener from body segment counts. Legacy `voiceover_script_alignment_failed` diagnostics are informational and must not block preview or render; an actively running timing step still does. When the Agent initiated voice export, pass its start time through `--voiceover-not-before <ISO>` so stale audio cannot be accepted.

If any repository script exits nonzero, do not stop after relaying the error. Read the `BOOK_VIDEO_DIAGNOSTIC` output and `tmp/last-workflow-diagnostic.json`, inspect the named inputs or subprocess, then fix and retry the narrowest failed step or use its documented fallback. A failed quality gate blocks activation of an invalid artifact, not the rest of the Agent workflow. Preserve the last valid artifact, continue every safe independent step, and ask the user only for actions that require their input or permission.

For episode work, reconcile `episodes/<book>/workflow-state.json` with `node scripts/workflow-state.mjs repair "<book>"` before resuming. Treat it as a recoverable cache of artifact state, not a source of truth above the files. After the user approves the validated script, run `node scripts/workflow-state.mjs approve "<book>"`. If a changed script leaves previously reviewed `illustrated` or `voiced` artifacts stale, recheck those exact artifacts and use `node scripts/workflow-state.mjs revalidate "<book>" <illustrated|voiced> --evidence '<step>@<active-script-version>:<review type> <checked>/<expected> <items> and result>'`; voiced review must confirm every current script line is heard, and illustrated review must cover the bridge plus every required atmosphere image. The CLI rejects mismatched step/version/count formats. Do not edit state JSON or fingerprints by hand. Other production steps reconcile from their artifacts and `production-report.json`. After embedding the verified video in the conversation, run `node scripts/workflow-state.mjs deliver "<book>"`. Never convert repeated failure into a terminal workflow state.

Initialization must be idempotent. It must not reinstall a verified skill, overwrite a valid key, reset user choices, or duplicate CSV columns.

## Book Selection

- If the user names a book, use it after verifying title and author.
- If `data/book-pipeline.csv` is missing, header-only, or has no usable candidates, ask one question covering preferred genre, emotional theme, or audience.
- With a preference, search according to it. Without a preference, search literary/philosophical books with strong emotional resonance for young adults.
- After every candidate search, write the complete result set to the local ignored `data/book-pipeline.csv` before recommending. Use `node scripts/record-book-candidates.mjs <candidates.json>` so fields are normalized and duplicate results are merged; never only present search results in chat.
- Recommend five candidates from the recorded rows and mark one top recommendation. Wait for book selection before drafting.
- When the WeChat Reading Skill is installed and configured, use it flexibly as the preferred research source for book metadata, popular highlights, and public reviews during book discovery and script preparation. Treat its results as research signals, not copy to reproduce. Public sources and user-provided material remain valid supplements or fallbacks when the Skill has no useful result.

## Book Metadata

Use `display_title` for folder names, visible labels, and scripts. Keep the exact source result in `source_title`; never overwrite it during normalization. Keep `source_book_id` and `source_channel` for provenance. Ambiguous editions, guides, summaries, or author mismatches require review.

## Production Gates

1. After book selection, create a provisional `script.csv` and run `node scripts/validate-script.mjs "<book>"` before showing any draft to the user. If it fails, shorten and revise internally, then validate again; never send an over-limit draft for approval. Only after it passes, send one active script for approval. The response must include the complete copy-ready voiceover in one Markdown fenced code block. Its first line is the display title in the form `《书名》`, followed immediately by every line to be read aloud. `script.csv` must also store that book title as `order=1`; following rows contain short, natural spoken subtitle chunks. Every row is read aloud. The title row is shown at the top of the intro and is not repeated as a bottom subtitle; each body row becomes one bottom subtitle. Do not put CSV headers, order numbers, author labels, timing data, or explanations inside the copy block. A `script.csv` attachment or file path is supplementary and must never be the only presentation; the whole block must be directly copyable into Jianying for audio generation. The copy block starts with the title row and nothing else — do NOT prepend a spoken opener such as `今天分享的是`; the shared intro template owns that opener, and the user copies the block straight into Jianying without typing anything extra.
Write the body as short, natural subtitle chunks: split long sentences at meaning and speech pauses, and combine adjacent very short phrases when they read naturally together. Body rows contain no punctuation or whitespace; do not rely on the renderer to split text. Use as many body rows as the natural phrasing needs, with a hard limit of 21 body rows (22 total including the title) and about 220 Chinese characters. The title row must match `brief.json`'s `display_title` (book-title brackets are allowed). This gate belongs to the drafting stage; audio timing and final rendering checks are secondary safeguards, not the first validation point.
2. Only after script approval, generate prompts, one separate `result-bridge.png` for the opening, and one AI atmosphere image per body scene. For `N` body rows, let `K = ceil(N / 5)` and create `atmosphere-1.png` through `atmosphere-K.png`; do not reuse images. The DP scene plan assigns each image to 3-5 consecutive body rows, favoring speech pauses and balanced scene durations.
3. Voice source:
   - Voice profiles are defined in `assets/template-audio/voice-profiles.json`. Omit `brief.json.voice_profile` to use the default `soft-male` (柔和男声); set it to `hong-kong-male` only when that voice is requested. Choose the profile before recording or generating audio; if it changes later, export or generate the voiceover again with the selected profile. Always pair the selected profile's intro and 10-second reference.
   - Auto-generation (TTS) is eligible only when all are explicit: it is native to the host's Doubao capability; it accepts a local/uploadable reference audio and text, clones the reference voice, and returns an audio file whose length follows the text; and it needs no API key/token, third-party account/login, subscription, credits, or per-use payment. Use the selected profile's reference from `voice-profiles.json`. If origin, clone support, free access, or file handling is unclear, fail closed to Jianying. Exclude plain TTS, browser/Web Speech, macOS `say`/system voices, and paid external providers. For eligible auto-generation, use the approved `script.csv` rows in order, preceded by the exact spoken phrase `今天分享的是`. Clone the whole sequence in ONE pass; leave at least 0.4 seconds of clear silence after the opener so FFmpeg can separate it from the book title. Never use an intro as the clone reference. Punctuation guides pauses but must not be vocalized. Save the combined opener, title, and body to `episodes/<book>/audio/body-voiceover.raw.mp3`; do not generate lines separately and splice them.
   - Keep the generated greeting at its natural speed; do not time-compress it to finish before the page turn. FFmpeg pads the remaining intro time with silence so the generated intro matches the selected profile's intro exactly; the greeting may continue over the page-turn animation.
   - Run `node scripts/finalize-generated-voiceover.mjs "<book>" [script-version]`. Whisper checks TTS text only; any suspected mismatch, duplication, ASR variance, or unavailable output is a review warning and does not block audio finalization. FFmpeg silence boundaries separate the generated opener from the script audio; the opener is padded to exactly the selected profile's intro duration and replaces it for that episode. The title and body are processed to canonical `body-voiceover.mp3`. If no opener boundary is detectable, report a warning, keep the full TTS audio and selected profile intro, mark the voiced result for Agent review, and continue without using Whisper timestamps.
   - Otherwise ask exactly: “请在剪映用当前声线（默认柔和男声）朗读 script.csv 全部口播行（第一行是书名），导出 mp3 到 episodes/<书名>/audio/body-voiceover.mp3 后继续。” Then run `node scripts/finalize-generated-voiceover.mjs "<book>" --source jianying`; it reads that export, skips Whisper, and normalizes it to the canonical path. Jianying exports carry a high-frequency noise floor; finalization denoises them (afftdn) before the story preset so loudness normalization cannot amplify hiss between sentences. Jianying uses the selected profile intro. For either source, run `node scripts/create-body-timings.mjs "<book>"` afterwards to produce silence-boundary timings. `script.csv` is the subtitle text truth; Whisper text is content-check evidence only, never caption text.
   - Keep `body-voiceover.raw.mp3` as the original voice master. Do not downsample or downmix the master for recognition. If the installed Whisper path requires 16 kHz mono input, make a separate recognition-only copy and leave the master intact. Preserve the provider's original valid MP3 settings; do not impose a fixed bitrate floor.
   - Gate policy: physical audio quality (sample-rate/bitrate floors), long leading silence, suspected TTS content differences, and unavailable ASR are warnings for review, not gates. Whisper timestamps are never used for timing. Jianying never invokes Whisper.
4. Mix the shared intro, gear SFX, and a user-selected or randomly chosen BGM. Render the final video only after the relevant media is present.
5. Replace old episode media only after the new output passes technical checks. Keep one active script, prompt set, image set, audio set, and render.
6. After a final render or preview succeeds, inspect representative frames, complete the pending Agent checks in `production-report.json`, and embed the actual local media in the same reply with an absolute-path Markdown media reference, for example `![最终视频](/absolute/path/to/final.mp4)`. Never provide only a filesystem path and ask the user to locate or open the file. Include the path and brief technical metadata below the preview as supplementary text. Frame inspection must follow the bounded procedure: (a) pick the right timeline for the artifact being checked — the standalone body preview (`tmp/preview-<slug>/body/renders/body.mp4`) burns subtitles on its own timeline, so a caption at `T` in `body-timings.json` appears at `T`; in the assembled FINAL render it appears at approximately `T + measured selected intro-audio duration` (currently about 3.03s). The 2.38s value is the scroll-animation endpoint, not the final-render body offset; (b) sample a caption's mid-window (40%-80% of its display interval), never its fade-in/fade-out edges, where opacity is ~0; (c) check 3-4 representative captions (early, middle, final) rather than every row; (d) extract frames with an exact seek (input after `-ss`) so the sampled time is accurate. A caption \"missing\" at an edge time is not a render defect; re-check it at the mid-window before investigating further.

The intro book list is a fixed six-book template list stored in `templates/shared-video-template/intro/default-book-list.json`. It is independent of `book-pipeline.example.csv`, and the target book may appear in the rolling list before the final reveal. Placeholder labels such as `书名一` or `作者一` are forbidden.

If the user explicitly requests fully automatic production, the script approval gate may be skipped for that episode only.

## Visual And Audio Rules

- Use the shared template in `templates/shared-video-template/` as the only visual baseline.
- Keep the glass-shard intro, rolling list, stable title/author, atmosphere-first body, slow push-in, crossfade, and white text with black shadow.
- Meaningful visuals must be AI-generated bitmaps. Do not use SVG as the main visual.
- Do not use card UI, visible watermarks, copied frames, book-cover mockups, or literal image prompts that weaken atmosphere.
- Body subtitles use every body row after `order=1` from `script.csv` as exact text truth and `body-timings.json` when valid. The spoken order-1 book title is shown at the top of the intro and is not repeated as a bottom subtitle. Timings come from silencedetect speech boundaries; missing or stale timings trigger a visible warning and automatic fallback to speech duration or script hints rather than blocking preview or render. Long Chinese lines must wrap within the 720px frame and remain visible.
- Before accepting a generated image set, inspect the bridge and every atmosphere image together and record each frame's subject, scene/composition, and dominant color direction in the prompt or review notes. Keep one distinct atmosphere image per DP scene of 3-5 caption rows; avoid repeating a person, scene, or composition across images unless the story needs continuity. Similar color temperature alone is not a rejection reason.
- Keep each body script row as a short spoken subtitle chunk without punctuation. Split long thoughts at natural meaning or speech pauses; combine neighboring tiny phrases when that reads naturally. Preserve each script row verbatim as its subtitle text.
- Keep videos under 60 seconds unless the user explicitly changes the limit.
- Music, SFX, and voiceover assets may be committed only when the user has the right to redistribute them. A “learning and exchange only” notice does not grant redistribution rights; do not add new media without permission from the relevant rights holder.
- Run long renders in a persistent terminal/execution session and poll until the process exits; verify its exit status and artifacts before updating workflow state. Avoid detached `&`/`nohup` runs that lose failure diagnostics.

## Script Rules

`script.csv` rows are the approved subtitle truth AND the alignment contract: each row must be ONE complete spoken unit — a short, standalone sentence with NO internal comma/period/question-mark pause — because silence boundaries treat each pause-separated speech segment as exactly one subtitle. A row with internal punctuation gets split into multiple segments by silencedetect, breaking the segment-count == row-count check and degrading alignment. Keep rows short (roughly 4-14 characters); the renderer may visually wrap a row internally but never relies on punctuation inside a row. Never rewrite approved script wording; if wording must change, get the new version approved first and keep one active version.

When the content check marks the first, book-title row as non-exact, treat it as a possible Whisper error and inspect the corresponding voice audio before accepting or rendering it. If the audio does not clearly confirm the approved title, stop and ask the user; keep the approved script as subtitle text.

Read `docs/book-video-playbook.md` before drafting, and study all three scripts and their analysis in `assets/reference-videos/文案与共鸣分析.md`. Borrow the emotional hook, focused escalation, self-projecting lines, and the way the book voices the viewer; do not reuse the original wording. The first line must immediately create resonance. Use short, natural lines and concrete scenes. Let the book support the viewer's emotion instead of becoming an academic summary. Avoid “你是不是”, “不是……而是……” formulas, mechanical parallelism, arrogant instruction, and CTA language. End with emotional aftertaste.

When WeChat Reading is available, consult its book details, popular highlights, and public reviews before drafting so the script has concrete material and a reliable emotional entry point. Use the Skill to inform the writing, not to copy long excerpts or replace independent judgment.
